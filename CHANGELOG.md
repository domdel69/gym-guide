# Changelog

Per-version change notes for Gym Guide, newest first. Extracted from the living plan on 2026-11-08; the commit for each release is in the README table. Tags: [S] stated by the user, [O] observed, [I] inferred, [?] unconfirmed.

## Version 0.28 changes

(1) Tab bar, second attempt. His 0.27 screenshot showed the bar cut off at the same height as before, with a band below in the manifest background colour (#0d141a), not in the new `<html>` colour: on his iPhone 11 in home-screen mode, iOS stops the web view about 48 px above the screen edge and paints that band itself, so nothing can be drawn there [O from pixel colours; cause in iOS unknown]. The 0.27 screen-height rule is removed (body back to the window height) and so is the `<html>` colour. When the web view is more than 20 px shorter than the screen in app mode, `html.shortvp` gives the tab bar the page background colour, no blur and no safe-area padding, so the bar and the iOS band read as one block with the icons in its upper part, like native tab bars. The Affichage line in Réglages > Application now says "vue courte oui/non". Light mode: the band stays dark (manifest colour), known limitation. (2) Repo rule: changes go through a branch and a pull request, never straight to main.

## Version 0.27 changes

(1) [superseded in 0.28: the band is outside the web view] Tab bar: his iPhone 11 screenshot showed an empty band of about 48 px under the bar, filled with the page colour, while iOS still reported a bottom safe area, so the body ended above the screen edge [I: in home-screen mode iOS reports a window height shorter than the screen]. Body now sized by `--apph`: in standalone mode, and only when iOS reports a bottom safe area, the screen height in the current orientation; otherwise `innerHeight`. While the keyboard is open, `--vvt`/`--vvh` from the visual viewport as before. `<html>` takes the solid tab colour (`--tabs`), so any band left under the body extends the bar instead of leaving a hole. Bar taller (54 px buttons, 26 px icons, equal top and bottom padding of 45% of the safe area, so the icons sit in the middle). Réglages > Application shows a one-line "Affichage" diagnostic (window, screen, visible area, bottom margin, app mode, height used) to confirm the cause on the phone. (2) Code review fixes: Content-Security-Policy meta (scripts from the site only, frames from youtube-nocookie only, no plugins, no form posts); imported backups are cleaned field by field (dates, ids, numbers, text length) before use, so an edited file cannot inject HTML; two unescaped values escaped; the service worker caches only complete 200 responses and serves the start page offline only for navigations; a failed save now warns once instead of failing silently; persistent storage requested; set figures also saved 0,5 s after typing (target frozen at the keystroke), so nothing is lost if the screen locks before leaving the field.

## Version 0.26 changes

(1) Stretch pictograms replaced by photos from Free Exercise DB (public domain, github.com/yuhonas/free-exercise-db; credited in `img/README.md` and on the stretch screen); two frames alternate; the commercial example sheets he attached were not copied (copyright); photos not illustrations, none for sphinx or doorway chest, so "Overhead reach" and "Chest opener (elbows back)" replaced them; stretch names EN first, FR second. (2) Countdown: ▶ per set on the side plank (duration field, default 45 s, "Tiens" timer), "Minuteur" card on elliptical and bike (±30 s, saved per exercise on the phone, `settings.dur`); same beep at the end. (3) Tab bar: body now fixed to the screen edges (the 0.25 version used the visual viewport height, which left a gap under the bar on the iPhone, cause inferred from his screenshot), slimmer bar, safe-area padding reduced. (4) Late beep: cause found in the code, a beep scheduled on a suspended Web Audio context played at the next tap (start of the next set); now the beep is never scheduled on a suspended context, fires from a timeout at the exact end, and is skipped if more than 2.5 s late (iOS suspends the page when the screen locks; a beep then cannot sound on time; a silent keep-alive audio would pause his music, not done).
